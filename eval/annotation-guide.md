# T07 六道问答开发集：人工标注规则 v1

状态：2026-09-28 冻结，适用于 [`qa_cases.jsonl`](qa_cases.jsonl) 的 D1—D6。首条已看过答案的真实演示仍是探索性案例，不能追记为预注册题；这六题是固定两篇论文上的开发检查，不是独立留出集。冻结的是问题、固定版本与 PDF 哈希、编号要点、等价表达、关键错误和原文位置；修订、ready 索引、Job/attempt/AnswerRun ID 属于实际执行绑定，必须在**每题排队前**记录，不能因回答内容而改题。事实错误需另存带新版本的案例及修订理由，不覆盖原行。

## 题目与整题判定

D1—D4 的每个编号必答点按“明确且正确覆盖”为 1，否则为 0；含糊猜测或只答对其中一部分记 0 并说明。接受案例中列出的等价表达，补充信息不进分母。关键事实错误、与固定材料冲突的结论和越界概括单列；即使必答点全对，只要有关键错误，整题仍不通过。整题通过要求全部必答点覆盖、无关键错误，并且每个必答事实有可定位且真正支持它的答案附带证据；D4 两篇各自的事实须有对应论文证据。材料充分却拒答是 `wrong_abstention`，不通过。报告逐题覆盖分子/分母，并将整题通过数另报；四道充分证据题共有 11 个编号必答点。

D5—D6 单独按案例中的“结论＋具体缺口”判定，不混入上述 11 点覆盖率。D5 必须说明固定论文没有目标日期的逐站可用性核查；“现在全部可访问”和“现在已有网站不可访问”都不能由这份 PDF 推出。D6 必须拒绝把两篇局部百分比相减当成相同任务与预算下的提升，并指出缺少共同任务、可比指标及执行条件。只说“信息不足／不知道”而不说明缺口不通过；编造现况或性能提升也不通过。拒绝无从得知的结论不需要引用来“证明不存在答案”，但提到的论文事实或数字仍需相应证据支持。

## 事实正确性、引用与证据支持

从答案原文拆出能独立判断真假的全部实质性论断，拆开并列事实、数字、比较和机制描述，合并重复表述并保留原文位置；六题全部核查，不抽样。每条论断分别记录两项：① `corpus_verdict`，人工在允许的固定 PDF 中查证事实本身；② `cited_evidence_verdict`，只检查**该论断实际附带**的保存证据能否支持它。两项都可用 `supported`、`partially_supported`、`unsupported`、`unverifiable`；引用项另可用 `missing_citation` 或 `mapping_failed`。在别处找到正确原文，不能替答案的错引补分；事实正确而未引用应是 corpus supported、引用 missing_citation。跨文献归纳允许两篇证据合起来支持合理推断，不要求原句逐字出现；但缺任一必要论文证据不能算引用充分。

分别报告“固定 PDF 中事实完全支持条数／全部实质性论断数”和“答案所附引用完全支持条数／全部实质性论断数”；`partially_supported`、`unsupported`、`unverifiable` 和缺引用分别列数，`unverifiable` 不从分母剔除。若答案没有可评的实质性论断，两种支持率都记 `N/A`，不能记 100%。展示引用按组核对能否导航到正确论文和保存原文；`raw_answer` 中每次出现的 Context ID 另按出现次数核对映射，格式化时消失的原始引用仍留在原始分母。引用映射成功只证明找到了片段，不证明片段支持论断。上游页段标签若为 `unverified_upstream_label`，人工核查另记真实 PDF 页与章节／表号，不能冒充已核准页码。

为减少判分分歧，运行前固定以下边界判例：D1 答 56、55 却不写 111，覆盖为 2/2，111 不扣分；答对 56、55 后又声称“两类都是文本题”，覆盖仍为 2/2 但有关键错误，整题不通过。D2 数字答对却只引用数据集外的片段，事实可判正确、引用支持不通过。D4 只给 BEARCUBS 的证据而没有 WebCanvas 的相应证据，四点即使表面答全也不能整题通过。D5 仅说“我不知道”，或断言“现在有网站不可访问”，都不通过。D6 将 65.8% 与 23.1% 相减作为同条件提升，不通过。

## 执行、可观察性与复现

先记 Job 是否成功、是否有可读 AnswerRun，再评回答；失败、截断、拒答和重试都留在六题分母及逐题记录中，Job 成功率和答案通过率分开。适配器只有在上游 `status=success` 且会话 `has_successful_answer` 为真时才映射 `reported_sufficient`；无答案等条件还会覆盖该标签。因此它只是上游经适配的信号，**不是人工确认充分**。分别记录外部搜索、用户选择、PDF 下载、解析、索引、库内检索与生成的可观察状态；无法从保存产物定位的阶段写 `UNOBSERVABLE`，不从最终答案倒推。

每次执行保留案例版本、论文版本/PDF SHA-256、修订/索引/Job/attempt/AnswerRun ID、实际模型角色名称、可安全保存的提示词模板与检索配置及其哈希、依赖版本和代码身份。当前目录没有 Git 仓库，`code_commit` 应明确为 `null` 并在执行时保存相关源码文件的哈希清单；现有 AnswerRun 仅保存部分有效配置，完整模型请求/最终供应商提示词若不可观测就写 `UNOBSERVABLE`，不复制含密钥的配置。首轮和任何重跑分别存新记录，保留原结果及重试原因。用量按原始聚合口径记录，未知角色请求数、Embedding token、费用写 `unknown`，不能写 0；缓存和重试另列。报告每题及总计的分子分母，明确这是开发集结果。
