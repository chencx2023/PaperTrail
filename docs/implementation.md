# PaperTrail 实现说明

主界面提供“检索论文”和“论文问答”。检索从用户确认的英文关键词出发，可通过最多三组查询和 RRF 合并固定版本候选；RRF 只负责融合检索顺序。用户显式点击“按摘要筛选”时，后台分批检查当前完整候选池，最多60篇、每批最多10篇，完整摘要不截断。通过核验后按阅读建议排列，同档保持原检索顺序。未筛选和依据未核实是独立状态，后续显式补筛只处理缺项。

arXiv 搜索整体失败时，普通执行器调用 OpenAlex 的 arXiv 集合做原关键词单路检索，最多核实八篇。候选题目、摘要、作者及具体版本由 arXiv 摘要页与提交历史确认，缺少版本的页面不进入可导入清单。备用结果不冒充多查询 RRF，界面显示来源。首选失败、备用 JSON、原文 HTML 与哈希分别保存并可离线重放；只有成功且数据库提交后的结果才发布缓存。API 与原文页面分别遵守服务端冷却，共享串行请求及至少三秒间隔；外部两侧均失败时保留双侧原因。

最多选择10个固定版本。一次“准备并进入问答”保存意图，持久化执行器依次导入、冻结成功论文和准备索引；部分失败保留成功论文，全部失败或索引失败时暂停问答。解析和嵌入结果只在配置及身份兼容时复用。

完整论文池和当次回答范围分别保存。用户调整参与范围后，显式生成才冻结独立子修订及其索引，未选论文不能进入该索引。刷新、查看历史、改勾选和点击引用不提交新任务；响应丢失的提交由用户使用原幂等键恢复。任务、尝试、报告和版本关系校验防止迟到结果覆盖当前操作。

PaperQA2 是固定上游依赖。应用层配置角色模型、回答提示、原文优先的上下文选择及保存证据，没有修改上游核心算法。最终上下文按相关性、去重及来源多样性装入24000个本地估算token预算，不使用固定六片段截断；估算不等于供应商计费。回答长度根据问题及证据决定，最终输出仍有模型预算。

公开配置模板启用 v34 compact_repair：Agent 仍可按需多轮调用论文搜索与证据工具；生成阶段采用提纲、整份复核两次模型调用。提纲按问题组织直接回答、带原文编号的事实及缺口。复核输入由程序先绑定每条事实当前实际引用的原文，再交模型比较结论、主体、条件及适用范围，删除或收窄引用不支持的附加限定；同时核对证据缺口，保留可回答的部分。程序执行结构、来源编号及作用域校验，评价标准部分直接呈现选中原句，其余部分保留经复核的解释。程序校验不等于语义正确性的形式证明。

原文窗口只从当前绑定索引的相邻文本中按重叠关系续接，保留偏移和原文身份，不引入范围外文献。提纲、复核原始输出、上下文与引用映射随答案保存。Flash 用于所有语言角色；仅两阶段生成启用高推理，单次输出上限32768、超时180秒，Agent 默认总时限500秒。已有 Agent 选择仅对指定临时服务端错误有一次受限重试，认证或余额错误不以额外生成探测；这不意味着整次问答只有两次 API 请求。解析失败或引用身份不合法时不发布该答案。

前端先按保存原文、引用身份和Unicode偏移校验，再渲染Markdown及数学。显示层合并段尾同篇论文引用，保留每次出现位置及对应片段。引用打开按论文组织的折叠来源表，显示保存摘要、原文及经固定版本与哈希核对的PDF。页码匹配可能未知或多处命中，旧答案不猜测改写。

研究历史连接检索、准备范围及答案。新检索创建记录，首次回答补全该记录，后续重新生成保存新记录；编辑输入不新增历史。手动改名不会被问题覆盖。

临时分享使用独立数据库与访问凭证，模型Key留在服务端。每次分享限制准备10次、问答10次、摘要筛选10次、检索建议与扩展合计20次，并有每分钟20次及总计120次修改请求限额。旧接口和重试归入原操作，内部自动衔接不重复计数。分享启动器验证HTTPS访问保护和执行器状态后才给出链接。
